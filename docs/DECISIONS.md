| 2026-11-09 | VERIFIED (2026-11-09, read from installed `@netlify/blobs` 11.1.6, `@netlify/runtime-utils` 3.0.0, `@netlify/zip-it-and-ship-it` 16.6.0 and the Functions v2 bootstrap shipped in a built zip): production `SERVER_ERROR` on `/v1/console/state` came from `import("@netlify/blobs")` failing with `ERR_MODULE_NOT_FOUND` (error name `Error`, 5-8 ms). ## Known gaps (documented, not fixed yet)
- Known limit: the scam rules are deliberately narrow (see `api/src/verdict.ts` and `api/src/companies/`). A phrase like "pay now or your power is cut", with no time word (today, tonight, immediately, within N hours), no link and no phone number, is not flagged. The reply is then "no matching notice" with "do not act on it yet" and the official channels, and the first reason says that finding no known scam patterns does not mean the message is genuine.
- Proof Code: no expiry, no one-time use, no rate limit on wrong guesses. A code can be reused and guessed (10,000 possible codes per company).
- "Matching notice" means the demo account has a notice on file. It is not text similarity with the pasted message. GENUINE now also needs a valid Proof Code or a supplied sender on the company's official allowlist (fixed: a notice with a missing or non-official sender returns NO_MATCHING_NOTICE). Remaining gap: the sender is user-supplied and could be spoofed, so a notice plus an allowlisted sender is still not proof of origin; the Proof Code is the stronger check.
- Verify has no timeout simulation. T8 covers the 500 path only.
- Blobs storage is tested only against a fake store, not real Netlify Blobs. The deploy bundle was checked by building it with the same bundler a deploy uses and loading it in Node with a stubbed Netlify runtime, not on Netlify itself. Strong-consistency reads need `uncachedEdgeURL` in the runtime's Blobs context; the v2 bootstrap sets it, but it was not seen on a live deploy. Concurrent requests with the same new idempotency key are not atomic. Nothing of the console, Blobs or draft work has been deployed or run on Netlify yet.
- The console pages were checked in a real browser against a local server (memory storage), not on Netlify. The demo key is typed by the user and held in page memory only.
- Reports do not store message text, so the Scam Vaccine alert and the knowledge draft cannot describe what the fake message said.
